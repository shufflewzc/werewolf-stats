# 赛事接入指南

如果你正在组织狼人杀联赛、公开赛、邀请赛或长期系列赛，希望减少人工统计成本，并为选手和战队提供统一的数据展示页面，可以将赛事接入我们的赛事数据平台。

我们采用“双方协作”的接入方式：比赛方负责确认赛制、提供真实资料和比赛结果；我们负责赛事建档、规则配置、首次数据导入、结果校验和上线支持。完成首次配置后，比赛方既可以继续按模板提交数据，也可以使用限定赛事范围的负责人账号自行维护。

> **标准接入周期：1–2 个工作日。** 周期从必需资料完整、赛制及统计口径确认后开始计算。历史数据量较大、规则复杂或涉及定制开发时，双方另行确认排期。

## 基础介绍

| 比赛方提供 | 我们负责交付 |
| --- | --- |
| 赛事和赛季资料 | 建立独立的赛事、系列赛和赛季档案 |
| 赛制、计分及晋级规则 | 配置积分组成、榜单、分组和晋级展示口径 |
| 战队、选手和视觉素材 | 建立战队与选手档案，导入头像和队标 |
| 赛程与比赛结果 | 校验并导入场次，自动生成统计与排行榜 |
| 数据公开范围和授权确认 | 发布赛事、赛程、比赛日、战队和选手页面 |
| 一名固定对接人 | 提供首次接入支持及赛事负责人后台权限 |

## 需要提供什么

### 1. 赛事基础信息

以下信息用于建立赛事和公开展示页面。

| 内容 | 是否必需 | 示例或说明 |
| --- | --- | --- |
| 赛事完整名称 | 必需 | 例如“XX 狼人杀广州公开赛” |
| 系列赛名称 | 必需 | 例如“XX 狼人杀大师赛”；单次赛事可与赛事名称一致 |
| 赛季名称 | 必需 | 例如“2026 夏季赛”或“S2” |
| 举办地区 | 必需 | 城市或赛区名称 |
| 开始、结束时间 | 必需 | 如尚未确定，请提供预计时间范围 |
| 主办方及对接人 | 必需 | 姓名、联系方式及负责事项 |
| 赛事简介 | 建议提供 | 用于赛事首页和分享文案 |
| 主视觉、赛事 Logo | 可选 | 建议提供清晰的 PNG、JPG 或 SVG 文件 |
| 官方链接 | 可选 | 报名页、公众号、直播间或社交媒体链接 |

### 2. 赛制、计分和排名规则

请提供最终版赛事规则，或安排熟悉规则的负责人和我们共同确认。至少需要说明：

- 赛事阶段，例如定级赛、常规赛、季后赛和总决赛；
- 每个阶段的日期、轮次、分组和每队参赛场次；
- 采用战队参赛还是个人参赛；
- 单局积分如何组成，例如胜负分、投票分、行为分、特殊分和违规调整分；
- 战队总分和个人总分的统计方式；
- 排名依据、同分处理方式及是否计算场均分或胜率；
- 分组、升降级、晋级、直通和淘汰规则；
- 抽局、重赛、弃权、处罚或其他特殊情况的处理方式；
- MVP、SVP、背锅等荣誉是否启用及评选口径。

规则确认后，系统会保存对应的计分口径。赛事进行中如需修改规则，应先说明生效范围以及是否需要追溯历史场次，避免前后榜单口径不一致。

### 3. 战队和选手资料

最低限度需要提供战队名称、选手比赛用名以及所属关系。为了让公开页面更完整，建议同时提供：

- 战队全称、简称、队标和负责人；
- 选手比赛用名、所属战队和常用别名；
- 选手头像或定妆照；
- 队长、明星选手等需要公开展示的身份信息；
- 已有的战队或选手唯一编号。如没有，我们可以协助生成。

比赛方应确认其有权向平台提供赛事名称、队标、头像、照片和选手资料，并明确这些内容是否可以公开展示。非公开信息请在提交时单独标注。

### 4. 赛程资料

建议在赛事开始前一次性提供完整赛程；如赛程尚未锁定，也可以分阶段补充。每场比赛至少需要明确：

- 比赛日期；如需展示具体开赛时间，请在接入时单独说明；
- 赛事阶段、轮次和局次；
- 唯一比赛编号；
- 房间号或台次；
- 板型；
- 参赛战队和上场选手名单。

唯一比赛编号会用于匹配后续赛果，确认后不建议随意变更。

### 5. 每场比赛结果

使用我们的软件记录比赛结果并导出。


平台可以按赛事规则提供专用模板。请保留模板表头和工作表名称，不要合并单元格；同一名选手和战队应始终使用同一名称或唯一编号。上传前建议由比赛方安排一人复核胜利阵营、选手归属和积分。

### 6. 历史数据（如需补录）

历史赛季可以接入，但请尽量提供原始 Excel、最终榜单、赛程、规则版本和素材文件。我们会先评估数据完整度，再确认哪些指标可以还原。只有总榜而没有逐场记录时，通常无法完整计算角色、阵营、胜率和站边率等明细指标。

## 我们能为赛事提供什么

### 1. 赛事数据建档

- 为不同赛事和赛季建立相互独立的数据档案；
- 维护系列赛、地区赛事、赛季、阶段、战队、选手和比赛记录；
- 允许同一名选手关联不同赛事的赛季身份，并汇总个人生涯数据；
- 支持赛季负责人在授权范围内维护数据，避免跨赛事误操作。

### 2. 计分、校验和数据安全

- 根据确认后的规则配置计分项、榜单和阶段展示；
- 支持后台单场录入和 Excel 批量导入；
- 导入时检查比赛编号、阵营胜负、选手归属、积分字段和重复数据；
- 保留导入批次、处理状态和操作记录，支持对成功导入批次进行回滚；
- 对异常数据先反馈确认，不擅自修改比赛方的原始赛果。

### 3. 自动统计和排行榜

在原始数据完整的前提下，平台可以自动生成：

- 选手出场、胜负、胜率、总积分和场均得分；
- 阵营表现、站边率、得分率和存活率；
- 战队总分、比赛日榜、赛季榜和分组榜；
- 选手、战队、比赛日和单场比赛明细；
- MVP、SVP、背锅等赛事荣誉记录。

最终展示哪些指标，以比赛方提供的数据和双方确认的统计口径为准。

### 4. 公开展示与数据访问

- 赛事首页、系列赛页、完整赛程和比赛日页面；
- 战队页、选手页、单场详情页和排行榜；
- 网站和小程序端的公开浏览；
- 面向公开数据的只读 JSON 接口，便于经过确认的外部展示场景复用。

公开接口会受访问频率和数据权限限制。私有接口、第三方系统自动同步、直播数据实时接入等需求不属于标准接入，需要单独评估。

### 5. 赛事运营协作

- 为比赛方开通限定赛事范围的“赛事负责人”账号；
- 提供首次录入、Excel 导入和日常更正的基础说明；
- 支持战队资料维护、战队认领及相关审核流程；
- 根据需要启用胜率预测、比赛日报、赛季总结、战队总结或选手总结。

AI 总结和胜率预测属于可选辅助能力，基于已录入数据生成，不替代裁判判罚、官方赛果或人工审核。

## 标准接入流程

### 第 1 步：提交资料

比赛方提交基础信息、赛事规则、参赛名单、赛程、素材和一份真实样例赛果。我们检查资料是否足以完成建档和统计。

### 第 2 步：确认口径

双方确认赛事名称、赛季范围、比赛编号规则、计分方式、榜单规则、公开字段和账号权限。存在歧义的规则以比赛方书面确认结果为准。

### 第 3 步：建档和配置

我们建立赛事、赛季、战队和选手档案，配置计分规则、赛制阶段及负责人权限，并准备对应的数据模板。

### 第 4 步：样例导入

优先使用 1–3 场真实比赛试导入，检查参赛人员、积分、榜单和页面展示是否符合预期。

### 第 5 步：双方验收

比赛方重点核对：

- 赛事、战队和选手名称是否正确；
- 单场胜负、积分和特殊奖项是否正确；
- 战队榜和个人榜是否符合官方口径；
- 赛程、头像、队标和公开范围是否正确；
- 负责人账号是否只能管理约定的赛事范围。

样例验收通过后，再导入其余数据并正式开放赛事页面。

### 第 6 步：持续更新

比赛期间，比赛方可以按约定频率提交赛果，也可以由赛事负责人自行录入。发生更正时，请提供比赛编号、原值、新值和更正原因，以便保留清晰的操作记录。

## 建议时间安排

| 时间 | 工作内容 |
| --- | --- |
| 接入前 | 比赛方准备资料、规则、名单、赛程和样例赛果 |
| 第 1 个工作日 | 双方确认口径；我们完成建档、规则和权限配置 |

以下情况可能延长周期：资料缺失或反复变更、同名选手无法确认、历史数据需要清洗、计分规则无法直接表达、需要新页面或新指标，以及需要与第三方系统联调。

## 服务边界与常见问题

### 是否支持在线报名？

当前标准接入不包含独立的在线报名系统。参赛战队和选手名单通过战队档案、比赛补录及后台维护形成。如果需要报名表、资格审核或缴费流程，需要单独评估。

### 比赛方可以自己维护吗？

可以。首次配置完成后，我们可以为指定人员开通赛事负责人账号。该账号仅维护被授权的赛事范围；高风险或跨赛事操作仍由平台管理员处理。

### 可以沿用比赛方现有的 Excel 吗？

可以先提交样表评估。字段较完整时可以整理后导入；长期运营建议改用平台模板，以减少名称不一致、漏项和重复记录。

### 规则中途改变怎么办？

请先书面确认新规则的生效日期、适用阶段以及是否追溯历史成绩。涉及历史重算时，我们会先在样例数据上核对结果，再更新正式榜单。

### 能否定制页面、指标或自动同步？

可以提出需求，但不包含在标准接入中。新增页面、特殊统计指标、私有 API、直播联动或第三方系统自动同步，需要单独确认可行性、数据接口、工作范围和交付周期。

### 数据出现错误怎么办？

比赛方提供官方更正后，我们会按比赛编号定位记录，通过后台修改或回滚后重新导入，并再次检查相关场次和榜单。平台负责按确认口径计算，比赛方负责最终确认官方赛果。
